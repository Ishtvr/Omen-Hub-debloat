# Omen Hub++ 0.10.0-beta.4

- Replaced the system-painted frame and top tabs with a custom caption and left
  navigation. Native Windows move/resize, maximize, minimize, system menu and
  the existing safe close/tray policy remain. Minimum client: 820 × 500 logical px.
- Fixed incomplete software repaint after minimize/restore or tray return with
  a one-shot rendering-cache refresh. The same window, draft and Undo state stay
  alive; there is no periodic full repaint.
- Replaced the bottom status/error strip with dismissible notifications and
  selectable details. Errors persist; ordinary completion messages expire.
  Existing action buttons remain. Preset switching offers Save/Discard/Cancel.
- Restored standard HP mode selection directly on Overview, above custom presets.
- Manual Apply now gives precedence to the latest target. Waiting older targets
  are replaced; an active hardware operation finishes safely before the latest
  starts. Only the current completion updates the UI. A pending checkpoint is
  restored and verified before replacement; failed recovery retains its journal
  and prevents the new target. No controller process is killed.
- Includes the uniform form fields, bounded chart tools, visual theme gallery,
  shared HSV/HEX app/keyboard chooser and software refresh pacing from the
  unpublished beta.3 development checkpoint.

See [Validation](../VALIDATION.md) for the checks and measurement limits. Actual
screen-pixel checks follow minimize/tray transitions before any MCP screenshot,
because Slint's snapshot path can itself repair the partial-render cache.

Startup approval remains separate from manual selection and app startup. Existing
protected helpers are not replaced by a portable UI update. HP shortcut modes
retain their partial readback/restore limitations. This release does not add
hardware SET qualification, prove sustained 85 °C enforcement, or establish a
fully HP-independent controller lifecycle. Normal release builds omit MCP.
