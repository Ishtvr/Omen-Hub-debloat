# Omen Hub++ 0.10.0-beta.14

Battery behavior, a crash fix and tidier settings rows, on top of the curve
fixes of [beta.13](0.10.0-beta.13.md) (fan-curve click add/remove, GPU Shift
offset against the NVIDIA default). Software and UI validation plus read-only
device checks; no battery run was measured yet. See
[Validation](../VALIDATION.md).

## Battery behavior per preset

- Each preset has a **Battery behavior** field under its name: the preset that
  is applied automatically when the charger is unplugged while this preset is
  in use. Plugging in returns to the preset. The choice is kept with **Save**
  in `battery-presets.json`. **Battery optimized** is created on Save.
- The **Performance profile** row and the last-apply text under the preset
  name are gone. The Settings page no longer has a battery row; an older
  global choice still applies to presets without their own.
- Each direction first undoes the preset it leaves. A gaming preset's power
  plan, power mode and boost policy no longer stay active on battery.
- Signing in on battery skips a sign-in preset that has its own battery
  behavior; the dashboard applies that behavior and returns on AC.
- The switch state is bound to the boot, so a restart ends an old battery
  session. A battery-percent step no longer counts as a source change.
- Waits follow the OMEN Hub: 1 s after unplugging, 2 s on AC and after resume.
  A failed switch is tried again after 5, 15 and 60 s.

## Stability

- The dashboard crashed in `nvml.dll` on 22 November 2026 (and on 5 November
  with 0.9.0) while **Keep preset** held an NVML session. The GPU limit is now
  read by a disposable child process, like the dashboard telemetry. The
  trigger inside the driver library is not identified.
- The tray logon task restarts the dashboard after a failed exit (three times,
  one minute apart). A task from an older build is registered again at start.

## Power draw

- The fan helper reads the dGPU power state from the Windows device tree and
  asks the NVIDIA driver only while the dGPU is awake. A cool GPU (below 60 °C)
  is read every 30 s without a retained driver session; the chassis sensor
  every 10 s. A powered-down dGPU no longer counts as a failed sensor.
- Dashboard GPU telemetry and the keep-preset probe pause while the dGPU is
  powered down, on AC too. **Keep preset** checks every 60 s on battery.
- One notice per AC session when the battery loses five points although the
  charger is connected. No limit is changed automatically.

## Interface

- Settings rows are 48 px with label, round **i**, editor and unit on one
  centre line. The **i** follows its label; the unit sits inside the number
  field. Overview rows and the footer share one right edge.
- The message dialog takes the height of its text; an apply result lists one
  statement per line.

## Not done here

- Automatic lowering of the CPU limit when the battery drains on AC (the OMEN
  Hub does this) needs a load test first.
- Whether the dGPU reaches D3 with the fan helper running is unmeasured; the
  external monitor on the dGPU port keeps it awake on the reference desk.
  `scripts/measure-battery.ps1` records the comparison without writing
  anything.
