# Omen Hub++ 0.9.0-beta.2

Public beta, 29 October 2026. Supported hardware remains the tested HP OMEN 16-ap0xxx (board 8E35, BIOS F.13, Ryzen 9 8940HX, RTX 5070 Laptop). Other models do not inherit its hardware permissions.

## Install

Download `OmenHubPlusPlus-0.9.0-beta.2-Setup.exe` and run it. It installs into the protected `C:\Program Files\OmenHubPlusPlus`, registers the preset sign-in task and optionally the fan service, start with Windows (tray) and a desktop shortcut. When PawnIO 2.2.0 is missing, the optional **PawnIO** task downloads the official signed setup from [namazso/PawnIO.Setup 2.2.0](https://github.com/namazso/PawnIO.Setup/releases/tag/2.2.0), checks its SHA-256 and opens it for your confirmation; untick it to opt out. Without PawnIO the app runs, but CPU power, temperature and tuning stay unavailable. The C runtime is linked statically; no Visual C++ Redistributable is needed.

Uninstall from Windows Settings > Apps. It removes the tasks and program files, returns HPOmenCap to its saved start type if Omen Hub++ disabled it, asks before deleting presets and settings, and leaves PawnIO installed. The ZIP remains available for manual installation with the included scripts.

The executable and setup are **not code-signed**. Windows SmartScreen shows "Unknown publisher" on first start; choose **More info > Run anyway** after checking the SHA-256 against `SHA256SUMS.txt`.

## Changes since 0.9.0-beta.1

- Single instance: starting the app again brings the running window forward, also from the tray. The dashboard restarts itself with administrator rights once, so actions need no prompt each time.
- Start with Windows is a per-user logon task (tray or window); an old Run entry migrates automatically.
- Settings: preset on battery (applies a mode or preset on unplug and returns on AC) and **Disable HP OMEN Cap** with restore of the saved start type.
- Presets are no longer blocked by overlapping instructions: a V/F curve wins over a global core offset, per-core Curve Optimizer over all-core, and a non-Balanced power plan over the Windows power mode. A power mode without a plan selects Balanced automatically and restores the original plan.
- NVIDIA driver updates no longer block presets or the private V/F and offset controls; measured drivers are 617.14 and 617.42, others rely on readback and restore. Only a missing driver blocks them.
- CPU Tctl limit up to 100 °C (AMD Tjmax). Firmware originals outside the preset ranges are restored as found instead of blocking Apply.
- Settings: **Keep preset** (off by default). Firmware can reset CPU limits and GPU flags on its own, for example when a game exits. When on, the dashboard checks the applied preset every 5 s, rewrites only drifted values (PPT, Slow, TDC, EDC, Tctl, PBO, CO, cTGP, Dynamic Boost), logs each correction to `preset-hold.log` and stops for a value that is overwritten again after three rewrites in a row. Restore still returns to the state before the preset.
- The fan service records why it stopped instead of leaving a stale "curve" status.
- Preset editor: new presets offer only Reset and Save. Unticked fields show this device's own values (read from the firmware while no control ran since boot, stored per board/BIOS); Reset uses the same values and the driver's factory V/F curve.
- GPU power is now three separate preset fields: **cTGP** (on by default), **Dynamic Boost (PPAB)** and **TPP** (shared CPU+GPU budget in W). cTGP and PPAB are read back and restored individually; TPP has no firmware readback and is written unconfirmed before the preset. Ticking Dynamic Boost proposes cTGP on and TPP 72 W, so the full GPU limit no longer needs the Unleashed mode. The dashboard mode Balanced now also turns cTGP on; only Quiet turns it off.
- GPU curve fix: new presets, presets without a saved curve and **Reset** (preset editor and curve window, also in the compact view) start from the driver's factory curve with all deltas removed. Before, an applied undervolt plateau appeared as the default in every preset.
- Settings window: explanations moved into the "i" buttons; every setting shows label, control and "i".

## Known issues

- The fan service stopped once with exit code 1 during testing; its task restarts only at the next sign-in. This build records the cause in `fan-service-status.json`. Restart it by signing in again.
- A global GPU core offset stays unavailable while an individual V/F curve is active.
- The NVIDIA power limit (watts) is not supported by the driver on the RTX 5070 Laptop.
- Standby/resume, preset on battery, long-term stability of offsets and curves, and sign-in after reboot still need confirmation on the device.
